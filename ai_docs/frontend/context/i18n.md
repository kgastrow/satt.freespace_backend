# Frontend Internationalization (i18n)

Uses `react-i18next`. **All user-facing text must be internationalized.**

## Structure

| Path | Purpose |
|------|---------|
| `src/i18n/config.ts` | i18n initialization, exports `supportedLanguages`, `languageNames`, `defaultNS` |
| `src/i18n/index.ts` | Re-exports `supportedLanguages`, `languageNames`, `SupportedLanguage` type |
| `src/i18n/react-i18next.d.ts` | TypeScript type augmentation (only `common` namespace has types) |
| `src/locales/en/` | English translation JSON files |

**Currently supported language**: English only (`supportedLanguages = ['en']`)

**Known namespaces** (defined in `ns` array): `common`, `auth`, `dashboard`, `files`, `admin`, `platformAdmin`, `errors`, `settings`, `backend`

**Additional locale files**: `feedback`, `helpCenter`, `media`, `onboarding` (all lazy-loaded on demand like the rest)

**Note**: All namespaces are lazy-loaded via `resourcesToBackend`. The `ns` array just declares known namespaces for initialization.

## Usage

```typescript
const { t } = useTranslation()
return <h1>{t('auth:login.title')}</h1>

// Multiple namespaces
const { t } = useTranslation(['common', 'settings'])
return <span>{t('settings:nav.account.title')}</span>
```

**Key format**: `namespace:key.subkey` (e.g., `common:buttons.submit`, `errors:validation.required`)

## TypeScript Types

Only the `common` namespace has TypeScript type augmentation. Other namespaces use string keys without autocompletion.

```typescript
// src/i18n/react-i18next.d.ts
interface CustomTypeOptions {
  defaultNS: 'common'
  resources: {
    common: typeof import('../locales/en/common.json')
  }
}
```

## Translated Zod Schemas

```typescript
const createEmailSchema = (t: (key: string) => string) =>
  z.object({
    email: z.string().email(t('auth:validation.emailInvalid')),
  })

// Usage: const schema = createEmailSchema(t)
```

## Adding Translations

Add key to `src/locales/en/<namespace>.json`, then use `t('namespace:key')` in component.

## Adding a New Language

1. **Update config** (`src/i18n/config.ts`): Add to `supportedLanguages` array and `languageNames` record
2. **Create locale directory**: `cp -r src/locales/en src/locales/<code>`
3. **Translate all JSON files** in the new directory

The `LanguageSwitcher` component automatically appears when multiple languages are configured.

## Common Mistakes to Avoid

1. **Hardcoding strings** - Never use literal strings for user-facing text
2. **Wrong namespace** - Use the correct namespace prefix (e.g., `settings:` not `common:`)
3. **Missing translations** - When adding new languages, translate ALL namespace files

## Backend Response Translations

API responses include `message_code` (success) and `detail_code` (errors) for localization.

```typescript
import { getErrorMessage, getSuccessMessage } from '@/types/api'
const { t } = useTranslation(['backend'])

toast.error(getErrorMessage(error, t))    // backend:user.not_found
toast.success(getSuccessMessage(res, t))  // backend:announcement.dismissed
```

Translations in `src/locales/{lang}/backend.json`. Falls back to English if code missing.
