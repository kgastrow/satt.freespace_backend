# Assimilate Design Handoff

Take a design-handoff bundle (README + prototype src/) and assimilate it into the project's frontend agent context so every downstream module implementor produces brand-correct, pixel-faithful UI.

## Arguments

- `$1` — Absolute or workspace-relative path to the design handoff directory (must contain `README.md` and a `src/` directory of prototype JSX/HTML).
- `$2` — (Optional) ADW ID. If provided, log assimilation activity to `agents/{adw_id}/design_assimilator/`.

## What this skill does

Three writes to the agent-context layer, plus a conditional write to the frontend codebase if the scaffold exists. **Idempotent** — re-running on the same handoff replaces the previous output cleanly; re-running with a different handoff fully overwrites the brand surface.

### 1. Read the handoff

- Read `{$1}/README.md` cover-to-cover. This is the visual source of truth.
- Catalog the prototype files in `{$1}/src/`. Note which screens are defined (filename → screen-name mapping). Read each `.jsx`/`.html` file at least to the level of identifying the exported components and their screen IDs.
- Extract:
  - **Tokens**: color palette (brand + theme + semantic), typography stack + type scale, spacing units, radii, shadows, motion timings.
  - **Shape language**: slashed corners, parallelogram chips, hex clip-paths, any utility-class candidates.
  - **Screen catalog**: every screen with a header in the README under "## Client PWA", "## Online", "## Management Centre" (or analogous sections). For each: name, slug, README anchor, prototype file path, layout summary (3–6 lines).

### 2. Rewrite `ai_docs/frontend/baseline_context.md`

The existing file describes the generic stack. Insert a new section **at the top, immediately after the `# React Frontend Architecture Guide` heading**, before the existing `## Tech Stack` table. Use this exact header so it can be located on re-run:

```markdown
## Brand Design System (source: <handoff path>)

> **THIS IS LOAD-BEARING.** Every UI module implementor must read this section and the linked `context/design_system.md` before writing components. The design tokens, type system, and shape language below are non-negotiable — they define the brand.

[brand summary: 1 paragraph naming the dominant surface color, primary action color, accent reserve, display face, body face, shape language signature]

**Mandatory references:**
- Visual source of truth: `<handoff README path>`
- Token reference + screen catalog: `ai_docs/frontend/context/design_system.md`
- Prototype src (read before implementing the matching screen): `<handoff src/ path>`

**Core tokens (must land in `index.css` or the theme module on day one):**

[CSS-variable list of the brand palette + theme palette light/dark + typography font-family declarations + key radii + key shadows. Include the exact hex values from the handoff. ~30–50 lines.]

**Type scale (use these as Tailwind utility names or theme tokens):**

[markdown table copied/adapted from the handoff's type scale, with column "Tailwind / theme token" added showing the suggested utility name — e.g. `display-xl`, `eyebrow`, `mono-s`]

**Shape language utilities (must be implemented as reusable classes or component variants):**

[bullet list with CSS clip-path values for: primary CTA hex slash, parallelogram chip, dropped-corner chip. Include the exact polygon coordinates from the handoff.]

**Reserved tokens — do not use as general accents:**
- `--ls-gold` is for **Crown Coins / rewards moments only**
- [any other reserved tokens called out in the handoff]
```

If a `## Brand Design System` section already exists from a prior run, **replace it in place** rather than appending a duplicate.

Leave everything else in `baseline_context.md` untouched.

### 3. Create `ai_docs/frontend/context/design_system.md`

Full per-screen reference. Overwrite if it already exists. Structure:

```markdown
# Design System Reference

Generated by `/assimilate_design` from `<handoff path>` on `<ISO date>`. Re-run that skill if the handoff changes.

## How to use this document

If you are implementing a UI module and its plan contains `design_references`, you MUST:
1. Read the screen entry below for each referenced screen.
2. Open the linked prototype file and read the JSX before writing any component code.
3. Apply the brand tokens listed in `baseline_context.md` — don't invent colors, fonts, or radii.
4. Use the shape-language utilities for CTAs, chips, and drop badges — these are brand signatures, not optional polish.

## Tokens

### Color
[full color table from handoff — brand, theme-light, theme-dark, semantic admin-pill]

### Typography
[full type system: families, scale table with px sizes / line heights / weights / italic flag / use cases]

### Spacing & radii
[from handoff]

### Shape language
[CSS clip-path values, when to apply each]

### Shadows
[from handoff, light + dark]

### Motion
[from handoff — easing, duration, signature animations like the scan-laser sweep]

## Screen catalog

For every screen documented in the handoff, an entry of this form:

### `<screen-id>` — <screen-name>
- **Surface:** Client PWA in-store | Client PWA online | Management Centre
- **Theme:** dark | light
- **Prototype:** `<absolute path to JSX file in handoff src/>` — component `<ComponentName>`
- **Spec section:** `<handoff README anchor or section path>`
- **Layout summary:** [3–6 sentence summary of layout, key elements, signature interactions]
- **Required tokens / utilities:** [bullet list — e.g. "hex clip-path primary CTA", "stadium-gradient hero card", "scan-laser animation"]

[one entry per screen — typically 8–20 screens for a full handoff]

## Cross-cutting requirements

- Status bar reservations (iOS frame contexts)
- Touch target minimums
- Dark/light theme handling
- Reduced-motion handling
- Anything else marked as cross-cutting in the handoff
```

### 4. Detect frontend scaffold and seed `index.css` if present

Run this check: does `app/frontend/src/index.css` exist?

**If yes (established project re-running assimilation):**
- Read the current `index.css`.
- Insert or replace a `/* === Brand Design System (managed by /assimilate_design) === */` block at the top of `:root` with the CSS variables from §2 of baseline_context.md.
- Also ensure the Google Fonts `@import` lines for the three families are at the top of the file (skip if a self-hosted font setup is detected — i.e., if a `fonts/` directory or `@font-face` rules exist).
- Add `font-family` declarations for `body` and a `.font-display` / `.font-mono` utility if they don't already exist.

**If no (true greenfield — frontend not yet scaffolded):**
- Create `ai_docs/frontend/context/design_system_seed.md` containing the exact CSS-variable block, font imports, and shape-language utility classes that the **first UI module** must paste into `app/frontend/src/index.css` (or the equivalent theme entry point) as its first step.
- This file starts with: "# Seed instructions for the first UI module — apply once, then delete."

### 5. Report

Print to stdout, in this order:

1. Handoff path read.
2. Screens cataloged (count + list of screen-ids).
3. Files written: `ai_docs/frontend/baseline_context.md` (updated section), `ai_docs/frontend/context/design_system.md` (full rewrite), and either `app/frontend/src/index.css` (seeded) or `ai_docs/frontend/context/design_system_seed.md` (created).
4. Whether the frontend scaffold was detected.
5. Any warnings — missing prototype files referenced by the README, screens described in prose but with no JSX file, etc.

## Validation

- The "Brand Design System" section appears exactly once near the top of `baseline_context.md`.
- `design_system.md` contains an entry for every screen described in the handoff README.
- Every prototype file in the handoff `src/` is referenced by at least one screen entry (or noted in warnings if it's a shared/icon/utility file).
- The CSS-variable block in `baseline_context.md` is consistent with what's in `design_system.md` and (if applicable) `index.css` / `design_system_seed.md` — no drift between them.
